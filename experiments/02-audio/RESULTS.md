## 2-B 编译与 SDK 核对

bench、probe 的 release 构建均成功。未运行 mic/tap/both，未签名或申请权限。只运行 probe --help 验证启动。

核对了本机 CommandLineTools 和实际构建使用的 Xcode macOS 27.2 SDK：CoreAudio.framework/Headers/AudioHardwareTapping.h、CATapDescription.h、AudioHardware.h。创建/销毁 process tap 仍为 macOS 14.2 起可用；CATapDescription 的基础混音构造方法、tap 格式和 aggregate tap list 仍存在。bundleIDs 和 processRestoreEnabled 标为 macOS 26.0 新增。AudioHardware.h 另有 macOS 27.0 新增的 kAudioDevicePropertySuggestedReferenceDevice（VAD 回声消除参考设备），不属于本探针使用的 tap 创建链路。未发现该链路上标示为 macOS 27 的破坏性变更；仅有当前 SDK 无法证明所有历史版本都无变化，权限及实际录音行为仍需真机验证。Swift 导入的 processes 参数是 [AudioObjectID]，不能照 Objective-C 声明传 [NSNumber]。

## 构建与验证记录

- 首次构建暴露 Swift refined API 参数类型不匹配，改为 [AudioObjectID] 后编译及链接成功。
- 默认 Swift Build 构建器在 dSYM 生成时 Operation not permitted；加 -debug-info-format none 后完整构建成功。
- scripts/build.sh：成功；缓存、scratch、config、security 均放实验目录，使用 --disable-sandbox（SwiftPM 子进程沙箱）；未改 HOME、TMPDIR。
- bench generate：成功，600.000 秒、16kHz、mono PCM WAV。
- bench int8/fp32 × 1/2/4：六个配置全部完成，分别覆盖五个短文件和长输入。
- probe --help：成功；实际录音由用户运行。
- 未跑 bun test / bunx tsc：按本任务环境补充，以 Swift 构建与实际基准为验证边界。

## Open questions

- 用户真机上麦克风、全局/指定 PID tap 的授权、OSStatus、是否有声音、两路首帧差及长期时钟漂移还未验证。
- 在 SIP 开启设备复验权限；本机不能替代正常 TCC 环境验收。
- 需要真实多人、多设备和跨会话样本再确定声纹阈值；本实验不实现用户声纹筛选、会议例外和 History 写入。
- 持续录音 CPU、RSS、耗电和降采样音质仍待长时间真机测试；线性重采样没有抗混叠滤波，不作为生产方案定论。
