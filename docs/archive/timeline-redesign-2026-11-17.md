## 1. 为什么再改

上一轮上线后的回顾页，用户的感受是“一堆内容，没有去看的欲望”。实机看到的原因：

1. **时间互相重叠。** 当天前五件事的起止是 00:15–10:38、00:15–05:25、00:32–09:54、01:26–10:23、01:38–11:26。原因是上一份任务书规定“同一事项当天分成几段时合成一件事，起止取最早和最晚”。列表既看不出先后，也看不出某个时刻在做什么。
2. **给 Agent 的文字拿来给人看。** 项目页的“状态”是两百多字的验收清单，事项卡片上是“助手自报……”。这些是事项摘要，本来是给 Agent 接手用的。
3. **页面种类太多。** 回顾、历史记录、项目、事项详情、待确认各有各的版式和写法。
4. **时间轴和列表对不上。** 上面一行是没有字的细线，下面四行来源灰条，看不出哪块对应哪件事。

参考：ChatGPT 桌面端的 Computer History 只有一根时间轴，每条挂在一个时刻上，写“你做了什么”，来源用应用图标。它的短处是固定 10 分钟一条、很碎，没有一天的总览。

## 2. 决定

| 编号 | 决定 |
|---|---|
| L1 | 全产品只有一种内容单元：**一段**。一段是一次连续的活动，有开始时刻、标题、一两句“你做了什么”、来源图标 |
| L2 | 段按时间排，**互不重叠**，新的在上。同一事项当天中断后再继续，算两段 |
| L3 | 侧栏为：时间线、搜索、项目列表。底部是记录状态、暂停、设置。“回顾”改名“时间线”，“历史记录”和“待确认”不再是侧栏项 |
| L4 | 历史记录并入时间线：点一段，原地展开它包含的原始记录。页面底部一个入口“这一天的全部记录”，打开现有的原始记录列表 |
| L5 | 项目页是同一条时间线按项目筛选、跨天排列，顶部一行项目说明。去掉目标、状态、相关的人、进行中卡片 |
| L6 | 事项摘要只给 Agent，不作为给人看的内容。项目页留一个入口“新会话会带入的内容”，里面是现有的事项列表和纠错入口 |
| L7 | 待确认不单独成页：有待回答的问题时，时间线顶部出现一行，答完消失 |
| L8 | 时间轴上面一行画的就是列表里的段（同一份数据），带标签；来源行压成细线、不带文字标签。只画有活动的小时 |
| L9 | 给人看的文字仍由每日整理一次调用生成，不新增整理档位 |

本轮不做，留到主窗口验收之后：设置重排、模型只选一次、清除最近一段时间、首次使用流程、菜单栏面板改版、一天从几点算。

## 3. 一段是什么

现有的 `hub/src/distill/day-review.ts` 已经把当天的记录归成活动（事项、录音、聊天、AI 会话、零碎），每个活动带若干连续时间片（`spans`）。问题出在一个活动只产出一件事。

- 同一活动里，相邻时间片间隔不超过 30 分钟且合并后证据覆盖至少 60% 才连成一段。在真实使用日上核对每天的段数、阈值和覆盖率。普通工作日 8–20 段是观察指标。
- 两段交叠时，按证据实际发生的区间比较“用户说的写的 > 别人对用户说的 > 用户看过的”。有发言时刻按前后 2 分钟裁决。没有逐条时刻的长 AI 会话仅首尾参加用户输入优先级竞争。低优先活动的来源图标并入主段，属于其他项目的原文留在全天列表。
- 每段的开始时刻是它第一个时间片的开始。界面只显示开始时刻；时长放在展开后。
- 短于 5 分钟且没有归属的零碎活动不成段（沿用现有 `MISC_SECONDS`），在“这一天的全部记录”里仍可见。
- 每日整理的输入从“每个活动”改为“每一段”，输出仍是标题、描述、依据。写法规则不变（`review-redesign` 第 5 节）。一句话摘要仍从最主要的一段里选。
- 30 段上限同时用于每日模型和界面。超限先合并满足连续性与覆盖要求的最短相邻同活动段；仍超限时优先保留每个项目实际覆盖最长的一段，其余按实际覆盖时长补足 30 段。项目代表超出名额时，同样按实际覆盖时长选择。裁下且未出现在其他可见段里的记录在全天列表标注“未入时间线”。（Claude，2026-11-17）

改动前后各记一次每日整理的输入 token，写进汇报；增幅超过一倍就停下来说明。

## 4. 页面规格

### 4.1 时间线（默认页）

从上到下：

1. 小号日期，右侧是前一天、今天、后一天。
2. 一句话：大号衬线字。
3. 时间轴（见 4.2）。
4. 有待回答的问题时，一行提示（见 L7）。
5. 段的列表，新的在上。每段：
   - 左侧：开始时刻。
   - 标题。
   - 一两句描述。
   - 来源图标一行：应用图标优先，没有应用的用来源图标（录音、微信等）。不写文字，悬停显示名称。
   - 点整行原地展开：时长，以及这一段包含的原始记录（复用现有的 `SegmentRow` 展开和记录检查器）。展开区底部两个操作：“这段写得不对”“删除这段记录”。
6. 页脚：一行小字“内容截至 HH:MM”，规则不变。旁边是入口“这一天的全部记录”。

“这段写得不对”：用户写一句替换描述，按现有“用户写的内容优先于自动推断”规则保存，重新整理时不覆盖。实现前先说明用哪张表、是否需要改数据结构。
“删除这段记录”：走现有的删除流程，确认后真删。

正文限宽约 680pt。这一页不超过 4 种字号。

### 4.2 时间轴

改 `DayStrata.swift`：

- 上面一行（现在的章节行）改为画列表里的段，数据同源，不再读 `timeline`。段不重叠，标签放得下就显示，放不下不显示半个词，悬停显示完整标题。
- 点一段：列表滚到那一段并展开。拖选一个范围：列表只显示范围内的段，再点一下取消。
- 来源行：高度压到细线，去掉左侧的文字标签，悬停时显示来源名称。仍只画启用的来源。
- 时间范围只覆盖有段的小时，前后各留一小时；今天延伸到此刻。零碎记录不撑开时间轴。
- 缩放和平移保留。

### 4.3 项目页

- 顶部：项目名，一行说明（现有的“目标”压成一句，不超过 40 字）。
- 下面是这个项目的段，按天分组，新的在上，版式和时间线相同。
- 右上角一个入口“新会话会带入的内容”：打开现有的事项列表（进行中和近期暂停的事项、摘要、纠错入口）。这是事项摘要在界面上唯一出现的地方。
- 去掉“状态”长段、“相关的人”、进行中和已暂停的卡片网格。

### 4.4 搜索

- 现有的搜索移到侧栏第二项，独立一页：顶部搜索框，结果按天分组。
- 命中的段在前，命中的原始记录在后；点结果跳到时间线对应的段并展开。

### 4.5 去掉的入口

- 侧栏“历史记录”“待确认”。
- 事项详情页不再从时间线和项目页进入，只从 4.3 的入口进入。
- 代码先保留，不删文件；本轮验收后再清理。
