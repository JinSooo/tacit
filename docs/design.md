# record-anything 设计文档

> 草案 v0.1 · 2026-11-08 · 设计讨论已结束，尚未开工
> record-anything 是工作名，正式名称未定。

## 1. 定位

把一个人在各台设备上的活动（屏幕、声音、聊天、Agent 会话、浏览、命令行……）记成一条**文字版的 Computer / Mobile History**，再由云端大模型异步提炼成"在做什么、做到哪、卡在哪"，让 Codex、Claude Code 等 AI 工具**自己来读**这些上下文，而不是用户每次手动喂。

- **自用 + 开源（MIT）**：任何人都能自部署，数据只在自己的设备之间流动，不对外暴露服务。
- **覆盖一切**：工作、编程、生活。粒度是"知道在干啥"，不追求逐字。
- **History 是地基**：给人看，可浏览、搜索、删除、修正；Agent 读到的上下文只是 History 之上的一层派生视图，随时可以从 History 重建。

调研结论（2026-11）：采集层已经有人做（screenpipe、Omi、Dayflow 等），但没有人把多个来源合并成按项目持续维护的任务状态，也没有人把 Agent 会话当作数据源。本项目的价值在**汇总和提炼**，采集只做到够用。

## 2. 架构

```
 采集端（每台设备一个）                 中枢（v1 跑在 Mac 上）                       使用端
┌──────────────────────┐            ┌─────────────────────────────────┐        ┌──────────────────┐
│ Mac 菜单栏应用（Swift）│  加密批次   │ 接收 → 密钥拦截 → History 存储   │  hook  │ Claude Code      │
│ Android 应用（Kotlin） │ ─────────→ │        ↓                         │ ─────→ │ Codex            │
│ 外部插件（任意语言）   │  先存本地   │ 提炼：线程 / 项目 / 人 / 日记 /   │  MCP   │ 其他 AI（适配器） │
│                      │  能连再传   │       画像 / 当前状态             │        │                  │
│ 本地：VAD、声纹、转写、│            │        ↓                         │  网页  │ 浏览器：History、 │
│ 文本去重、黑名单       │            │ MCP 服务 · 网页 · 待确认列表      │ ─────→ │ 待确认、设置      │
└──────────────────────┘            └─────────────────────────────────┘        └──────────────────┘
```

**分工规则：采集端负责所有读取并持有系统权限；中枢只接收数据，不申请任何系统权限。**

- **每台设备转写自己录的音频**，中枢只接收文字、声纹向量和质量指标，不接收音频。唯一例外是待确认列表要播放的试听样本（见第 5 节）。
- **查看**：每台设备能在本地查看自己采集的记录（Android 应用里看本机的；Mac 采集端自带原生窗口，读同机中枢的接口）；中枢网页查看所有设备的。设备之间互相同步留到以后。
- Mac 采集端和手机走同一套协议，对中枢来说只是又一台设备。
- 中枢以后可以搬到别的机器（比如 24h 在线的 Windows），采集端和协议都不用改。
- 避免给 Node/Python 解释器开"完全磁盘访问"这类全局权限。

## 3. History 记录

### 3.1 粒度

采集端的底层事件（每次界面变化、每个人声片段）**不进 History**，只在设备本地的临时缓冲里。写进 History 的是按规则合并后的**活动片段**：同一应用、同一上下文下连续的一段。Mac 上一天大约几百条，可以像浏览器历史一样一页页翻。

### 3.2 字段

```yaml
id:          01JC8...            # ULID，在设备上生成；离线可生成，重复上传自动去重
schema:      1                   # 格式版本
device:      mac-m5
source:      mac.screen          # 来源插件，见第 4 节
kind:        span                # span（时段）| event（时刻）
t_start:     2026-11-08T14:02:10+08:00
t_end:       2026-11-08T14:27:45+08:00   # event 没有
t_received:  2026-11-08T14:28:01+08:00   # 中枢收到的时间，用于估算设备时钟偏差
context:                         # 按来源填有的字段
  app:       com.todesktop.cursor
  window:    mock.ts — ruilin-mock
  url:       null
  repo:      ~/Study/ruilin-mock
  cwd:       null
  chat:      null
  place:     null
people:      []                  # 指向"人"实体：说话人聚类 id、联系人
title:       Cursor · ruilin-mock · 25 分钟   # 简略版，一行；能用规则拼就不调模型
body:        |                   # 详细版：去重后的屏幕文字、带说话人的转写、消息列表
  ...
media:       []                  # 原始素材引用，每项带 expires，按保留天数清理
capture:     { method: ax, confidence: 0.95 }  # ax | ocr | asr | db | api | manual
sensitivity: normal              # normal | private | redacted
redactions:  0                   # 写入前被拦下的密钥数量（只记数量和类型）
dup_of:      null                # 重复记录指向代表记录
corrects:    null                # 修正记录指向被修正的那条
```

格式只在一份 JSON Schema 里定义，生成 Swift、Kotlin、TypeScript 三端类型。

### 3.3 各来源怎么切成一条

| 来源 | 一条记录 | 切开条件（起始值，跑起来再调） |
|---|---|---|
| 屏幕 | 同一应用、同一窗口/页面/仓库下的连续使用 | 切换上下文，或空闲超过 2 分钟 |
| 音频 | 一段对话，正文是带说话人和时间戳的转写 | 静音超过 60 秒 |
| 聊天 | 一个会话一段时间内的消息 | 消息间隔超过 30 分钟 |
| Agent 会话 | 一次会话，长会话按小时切 | 只保留用户输入和 AI 最终回复，丢掉工具输出 |
| 浏览器访问 | 每次访问单独一条 | — |
| shell、git commit | 每条命令、每次提交一条 event | — |
| 剪贴板、下载、拍照、来电、位置变化 | 一个 event | — |
| 照片 | event，只存识图描述、时间、地点，不复制原图 | — |
| 手动补写 | 用户写的一段话，可以补过去的时间 | — |

### 3.4 规则

- **写入后不再修改。** 记录属于哪个项目、哪个线程，存在单独的归属表里。重新聚类、用户纠正都只改归属表。
- **修正**是一条新记录：`source: manual`，`corrects` 指向原记录。显示和提炼都以修正为准，原文折叠保留。手动记录的可信度最高，自动推断不能覆盖它。
- **删除就是真删**：删记录、原始素材、全文索引；引用过它的线程、项目、日记标记为待重新生成。同步来源（微信库、浏览器历史等）下次会把它再导进来，所以留一个只含 id 和内容哈希的墓碑，防止重新入库。**已经发给云端模型的内容收不回来**，文档里要写明。
- **跨来源重复**：每条都保留，选一条作代表，其余 `dup_of` 指向它。列表和提炼只用代表；误判了也不丢数据。
  - Mac 和手机录到同一段对话：按校正后的时间重叠和转写相似度判断，按采集端随记录附上的质量指标（有效人声时长、音量、转写置信度）保留更好的一份。中枢没有音频，只比文字和指标。
  - 同一条微信消息来自手机通知和 Mac 数据库：按会话、发送人、内容、时间匹配，以数据库那份为代表。
- **时间**一律带时区。同步时估算各设备和中枢的时钟偏差，跨设备去重用校正后的时间。
- **人**是单独的实体。声纹聚类、微信联系人、电话号码在待确认列表里确认后才合并成同一个人；确认后按 id 回填，历史记录里的"说话人 B"全部显示成真名。

## 4. 数据源

### 4.1 Mac（v1）

| 来源 | 做法 | 权限 |
|---|---|---|
| 屏幕文字 | 切应用/窗口/标题/URL 时读当前窗口的辅助功能（AX）树；使用中每隔几秒检查一次变化。和上次比对，只保留新增文字。空闲用系统"距上次输入秒数"判断，不监听键盘 | 辅助功能 |
| Electron / Chromium | 每个应用只设置一次 `AXManualAccessibility`，反复设置会让前台卡顿 | 同上 |
| 终端 | 只取可见区域的变化，不读整个回滚缓冲 | 同上 |
| 应用、窗口、URL | NSWorkspace + AX；URL 读地址栏，或 AppleScript 读 Safari/Chrome | 辅助功能 |
| 剪贴板 | 每秒检查变化；带 `org.nspasteboard.ConcealedType` / Transient 标记的跳过；只记文字，图片只记一条 event | 无 |
| 文件 | 监听下载、桌面、文稿，只记"新建/下载了某文件"，不读内容 | 视目录而定 |
| 日历 | 读日程，音频"有会就保留"规则要用 | 日历 |
| Agent 会话 | 增量读 `~/.claude/projects/**/*.jsonl`、`~/.codex/sessions/**`（含归档后的 `.jsonl.zst`）；只留用户输入和最终回复；按 cwd 对应到仓库 | 无 |
| 浏览器历史 | 复制 Chrome / Arc / Safari 的 History 库后增量读 | 完全磁盘访问（Safari） |
| shell | 在 `.zshrc` 加钩子，记录命令、目录、退出码、耗时 | 无 |
| git | 从 shell 和 Agent 会话出现过的目录收集仓库，定时读新提交 | 无 |
| OCR（v1） | AX 读不到或正文过少时截图交给 Apple Vision（实测需要：微信、Zed），图只在内存里，用完即丢 | 录屏（可选；不开时这些应用只记应用名和窗口标题） |
| 微信（v1 之后） | 解密本地 SQLCipher 库；取钥方式做成可替换插件，预期每次微信升级都可能失效 | — |

AX 扫描约束（实验 0-B）：
- 只能读到当前桌面（Space）上的窗口，所以只读前台应用的 `AXFocusedWindow`，不做后台全量扫描。
- 每次扫描设元素数和时间上限（3,000 个元素、200 ms、深度 60），只遍历与窗口可见区域相交的元素。Mail 不设限时一次读出 158 万字、耗时 88 秒。
- 每个元素用一次 `AXUIElementCopyMultipleAttributeValues` 批量取角色、子节点、位置、尺寸，比逐个属性取快一到三倍；同层子节点按面积从大到小访问，输出再按文档顺序排。实测 14 个常用应用都在 50 ms 内读完、无截断。Electron 应用（Claude 桌面版）的树超过 40 层。
- OCR（Vision，accurate，中英）预热后微信约 0.2 s、Zed 约 0.5 s 一次；同一段至少隔 15 秒才再识别。用到 OCR 的段整段标 `ocr`、置信度 0.7。

不做：Mac 相册、iMessage（用户用 Android，价值不大）。

**插件**：调用系统接口的来源是 Swift 内置插件；读文件/数据库的来源是外部插件，任何语言都能写，由采集端启动，每行向 stdout 输出一条 JSON 记录。

### 4.2 音频（v2）

见第 5 节。Mac 上麦克风和系统声音分两路录。

### 4.3 Android：小米 14 Ultra / HyperOS（v3）

只用普通侧载权限：不写输入法、不 root，Shizuku 不作默认。

| 来源 | 做法 |
|---|---|
| 前台应用 | 使用情况访问（UsageStats） |
| 屏幕文字 | 无障碍服务 |
| 通知 | 通知监听，可拿到微信等消息预览（会被折叠、截断） |
| 音频 | 前台服务录音；微信语音/电话时麦克风被占用，录不到 |
| 电话 | 导入小米自带通话录音文件（路径待确认）+ 通话记录 |
| 照片、截图、文件、短信、位置 | 对应权限 |
| 剪贴板 | **拿不到**（Android 10 起后台不可读），接受这个损失 |

应用内能查看本机采集的记录，存在本地加密库里；离线时也靠这个库攒数据，能连上中枢再传。

首次安装要开约 5 项权限，再加 HyperOS 的自启动、省电"无限制"、多任务锁定，所以要做**分步引导页**：逐项显示已开/未开，一键跳到对应设置。HyperOS 升级可能重置这些设置，应用要能发现自己被关掉并提醒。另加一个手动补写的快捷入口（桌面小组件或通知栏按钮）。

## 5. 音频流程（v2）

```
采集端：人声检测（VAD） → 切成对话 → 声纹判断有没有"我" → 转写 → 对话内说话人区分 → 加密同步（文字 + 声纹向量 + 质量指标）
中枢：  跨对话说话人聚类 → 匹配声纹库 → 跨设备去重 → History 记录
```

| 步骤 | 位置 | 说明 |
|---|---|---|
| VAD | 采集端 | Silero VAD，没人说话的部分当场丢掉 |
| 切成对话 | 采集端 | 人声间隔不到 60 秒算同一段 |
| 声纹判断 | 采集端 | sherpa-onnx 声纹模型，按**整段对话**判断有没有用户；没有就不转写、不离开设备、不留记录。用户的声纹样本由中枢下发 |
| 转写 | 采集端 | 本地 SenseVoice（sherpa-onnx）。Android 用高通 QNN 调 NPU，不支持时回退 CPU；模型运行时下载并校验，不打进安装包。云端 ASR 可选 |
| 对话内说话人区分 | 采集端 | 需要音频，只能在录音的设备上做；每个说话人每 3 秒连续窗口算一个声纹向量，随转写上传 |
| 跨对话聚类、声纹库 | 中枢 | 只用上传的向量 |
| 跨设备去重 | 中枢 | 见 3.4 |

例外和规则：
- **即使没有用户声音也保留**：Mac 上开着会议软件，或日历上这个时段有会（应对"一句话没说的会议"）。
- Mac 两路录音按整段对话判断：麦克风那路有用户就转写整段。系统声音那路只在开会时转写，其他时候只用来去回声（避免把音乐、视频写进 History）。
- **试听样本**：这是唯一上传到中枢的音频。新说话人进待确认列表时，中枢向录到它的采集端要样本，采集端从还在保留期内的音频里截取，每个说话人不超过 3 段、每段约 10 秒；设备不在线时列表显示"样本待取"。样本作为保留天数之外的例外，标注后删除，只留声纹特征。麦克风那路的声音出现 2 段对话或累计 30 秒、系统声音那路出现 3 段对话或累计 2 分钟才进待确认列表。
- 用户的声纹不需要注册，在待确认列表里从样本中标出"这是我"。确认过的"我"的声纹向量下发给各采集端，用于上面的声纹判断。
- 用户在用 Mac、两台设备在同一网络时，手机暂停录音。
- 原始音频只留在录音的设备上，按保留天数清理（Opus 约 7MB/小时）。

三端必须用**同一个声纹模型**，否则声纹无法互相比对。

## 6. 提炼层

### 6.1 对象

| 对象 | 是什么 |
|---|---|
| 线程 | 一件连贯的事，可横跨多台设备和多个来源 |
| 项目 | 一组线程的长期归属：代码按仓库，其他按主题或人 |
| 人 | 联系人和声纹聚类合并成的同一个人 |
| 日记 | 每天一篇 |
| 画像 | 长期偏好、习惯、常联系的人、作息；每条附证据，可删可改；每周更新 |
| 当前状态 | 从活跃线程投影出的"此刻在做什么"，即注入给 Agent 的 now.md |

### 6.2 三层内容

每个对象都有：

| 层 | 给谁 | 内容 |
|---|---|---|
| 简略 | 用户默认看到的；Agent 自动注入的 | 一两句：在做什么、做到哪 |
| 详细 | 点开才看；Agent 按需读 | 目标、已定（附原因和生效时间）、被否决的方案、未决、下一步、相关文件/链接/命令/人、关键原话 |
| 证据 | 核对、纠错时 | 指回 History 原始记录 |

规则：
- **先写详细版，简略版只从详细版派生**，简略版里每句话都能在详细版找到出处。
- "已定"和"推测"分开写；推测要标依据和置信度。
- 决定被推翻时，旧条目标记失效并注明被哪条取代，不删除（双时态：事实何时成立 / 系统何时得知）。
- 每个对象带更新时间和置信度，Agent 能判断是否过时。
- 项目、线程的显著度按新近度和频率衰减（参考 Mylyn 的兴趣模型）。

### 6.3 处理节奏

全部异步；Mac 睡眠期间积压的数据醒来后补跑。

| 节奏 | 默认模型 | 做什么 |
|---|---|---|
| 每 5–10 分钟 | Haiku 5.5 | 新记录归入已有线程，或提议新线程；增量更新线程详细版 |
| 每小时 | Sonnet 5.5 | 合并/拆分线程，更新项目状态，重新生成简略版；新项目、新说话人进待确认 |
| 每天 | Sonnet 5.5 批处理 | 写日记；疑似完成的线程进待确认；合并重复线程；每周更新画像 |

模型只是默认推荐，每一档用哪个模型由用户配置（见 9.3）。

**归属线程的顺序**：先用确定线索（仓库/cwd、聊天对象、URL、人）→ 文本相似度 → 交给模型 → 模型置信度低的进待确认。

**门槛**（起始值）：
- 累计 15 分钟活动，或跨两次以上会话，才建线程；不够的只进日记。刷视频、零碎查资料只留在 History 和日记。
- 2 小时没有新记录：线程标为暂停。
- 3 天没动静，或出现完成信号（PR 合并、发版、用户说"做完了"）：进待确认问用户，**不自动标记完成**。

### 6.4 待确认列表

所有需要用户判断的事都在网页上这一个列表里，**不弹通知**，可以攒着一次处理：

| 类型 | 用户看到 | 操作 |
|---|---|---|
| 新声音 | 2–3 段样本，可播放 | 填名字 / 就是我 / 与某人是同一人 / 忽略 |
| 新项目 | 候选名称和依据（哪些应用、对话、文件） | 新建 / 并入已有项目 / 改名 / 不是项目 |
| 合并建议 | 两个项目可能是同一个 | 合并 / 保持分开 |
| 完成确认 | 这件事做完了吗 | 完成 / 继续 / 放弃 |

**不确认不阻塞**：先用临时标签（"说话人 A""未命名项目：xx"）往下处理，Agent 读到时带"未确认"标记；确认后按 id 回填。

## 7. 交给 Agent

### 7.1 方式

- **会话开始时注入**：SessionStart hook 带当前目录问中枢，注入当前状态 + 匹配项目的活跃线程简略版，**不超过 800 token**，附一行可用工具提示。会话压缩后重新注入。
  - Claude Code：hook 输出 `hookSpecificOutput.additionalContext`（必须嵌套，放顶层会被丢弃）；写在用户级 settings，不走插件（插件 hook 有已知 bug）。
  - Codex：SessionStart hook（需 `codex_hooks = true`，开工时核实）。
- **MCP（stdio，以读取为主）**：两边配置里只写一条命令（`bun …/hub/src/cli.ts mcp`），进程自己读数据目录里的 hub token 文件（0600） 再调用 hub 的 `/v1/agent/*`，token 不出现在任何配置文件里。（2026-11-08 确认，原方案是本机 HTTP）读取逻辑和审计都在 hub 里，MCP 进程只做转发。
  - `now()`：当前状态
  - `get(id, level)`：读线程、项目、人、日记；`level` = `brief` | `detail` | `evidence`，Agent 自己选读几层
  - `search(query, time_range)`
  - `timeline(range, device)`
  - 返回结果分页，控制单次大小。
  - `history_append(title, body, source_ref?, …)`：唯一的写入工具，见下。
- **Agent 只有一个追加工具**：它的会话本身就是数据源，会被自动采进来，纠错只在网页上做。唯一例外是用户明确要求"把这些存进来"（Notion 页面、自己整理的内容）时，用 `history_append` 往 History 追加：只追加、不改不删；同一外部条目重复写入去重，内容变了挂修正记录；写入前拦密钥；审计标注是哪个 Agent 写的。Codex 里这个工具每次都要用户确认。（2026-11-09 确认）
- **审计**：Agent 每次读了什么，在网页上留一条记录。

### 7.2 范围

- 在代码仓库里开的会话，只注入这个项目的状态和"当前"中与工作相关的部分。生活类内容默认不出现在编程会话里，只在 Agent 明确查询时返回。
- private 内容不自动注入，Agent 主动查询时可以拿到。

### 7.3 适配器

接入的 AI 工具做成**适配器**，一个适配器负责两件事：读这个工具的会话记录（作为数据源）、把上下文交给它（hook / MCP 注册）。v1 实现 Claude Code 和 Codex，之后扩展 Cursor、Gemini CLI、OpenCode 等。

安装命令（如 `ra agents install`）在写入 `~/.claude/settings.json`、`~/.codex/config.toml` 之前先展示改动；`uninstall` 原样撤销。

### 7.4 与 AGENTS.md / 记忆文件的边界

`AGENTS.md` 管"怎么做"，由人维护；本系统管"发生了什么"，由机器维护。系统可以**建议**把某条已定的事写进 `AGENTS.md`，但不自己写。

## 8. 隐私与安全

按"越早拦越好"分五道关：

1. **采集前不采**：密码管理器、钥匙串、银行、浏览器隐私窗口进黑名单；安全输入框跳过；剪贴板 Concealed 标记跳过；菜单栏和手机都能暂停（1 小时 / 到明天 / 继续），Mac 上有全局快捷键。暂停期间 History 只记一条"已暂停"。
2. **写入前拦密钥**：本地规则识别 API key、令牌、私钥、JWT（参考 gitleaks）+ 高熵字符串检测，替换成 `[已脱敏:类型]`。**密钥从不落盘**，Agent 和网页看到的也是脱敏后的内容。有本地记录库的采集端（Android）写库前也要拦，和中枢用同一份规则。
3. **发云端前**：private 不进提炼。人名假名化可选，默认关（按待确认列表确认过的名单替换，结果回本地还原）。
4. **本地存储**：数据库和原始素材加密（SQLCipher），密钥放 macOS 钥匙串，只允许本应用读取；Android 本地记录库同样加密，密钥放 Android Keystore。挡不住以同一用户身份运行的恶意程序，只是提高门槛。
5. **Agent 读取（防提示注入）**：History 里存的是不可信文本（网页、聊天、邮件）。用户常以跳过权限确认的模式运行 Agent，被注入的指令可能真被执行。
   - 提炼模型只写事实，遇到祈使句式内容改写成"某页面中包含一段指令"；
   - MCP 返回原文时标注来源，并说明这是数据、不是指令；
   - 自动注入只给简略版，尽量短。

**他人的声音**：默认只保留有用户参与的对话（加上会议例外），旁人闲聊、电视声音直接丢弃。开源文档写明录音的法律边界。

**敏感级别**：
- `normal`：正常处理。
- `private`：不进提炼、不进自动注入，Agent 主动查询时可以拿到（注意：Agent 读到的内容会发到其厂商的云端）。
- `redacted`：已脱敏。

## 9. 网络、同步与部署

### 9.1 网络

不依赖 Tailscale 或任何特定网络：

- **安全在应用层**：配对时 Mac 显示二维码（地址、公钥、一次性令牌），手机扫码；之后每批数据用 HPKE（RFC 9180）加密。
- **先存本地，能连再传**：手机可以攒几天数据。
- **中枢回传给设备的**（从配对起就要有，不等多端同步）：删除和修正，保证中枢删掉的记录在设备本地库里也删掉，设备上删的中枢也删；确认过的"我"的声纹向量；试听样本请求。
- **传输方式**：
  - 局域网直连（默认，Bonjour 自动发现）；
  - 任意可访问的 URL（Tailscale、WireGuard、反向代理、Cloudflare Tunnel 都行，由用户选）；
  - 中转信箱（以后再做）：用户自己的 S3 兼容存储，放加密数据，Mac 醒来再取。
- **中枢默认只监听 localhost**（网页、MCP）；配对设备后才开放局域网接收端口。

### 9.2 安装与目录

- 从源码安装：一个脚本完成创建自签名证书 → 构建并签名采集端 → 安装中枢为 launchd 服务 → 打开引导页。
- 数据目录：`~/Library/Application Support/record-anything/`。
- 备份 = 加密的数据库文件 + 钥匙串里的密钥。**丢了密钥就丢了数据**，用 `bun hub/src/cli.ts keys export` 导出恢复命令，状态页和安装结束时提示。
- 升级时做 schema 迁移，迁移前自动备份。
- 卸载：移除 launchd 服务、Agent hook 和 MCP 注册，数据是否删除由用户选。
- 不收集任何遥测。

### 9.3 模型配置

模型提供方做成适配器，v1 支持三类：

| 类型 | 说明 |
|---|---|
| **API** | Anthropic 接口、OpenAI 兼容接口（可接 DeepSeek、豆包、本地 Ollama 等） |
| **中转站** | 同上两种接口，填自定义 base URL + key，支持把系统里的模型名映射成中转站的模型名 |
| **账号登录（CLI 后端）** | 调用本机已登录的 CLI：`codex exec` 走 ChatGPT 账号登录，`claude -p` 走 Claude 账号登录。不自己保存或复用它们的令牌 |

- 分钟、小时、每天三档分别配置模型，每档可以选不同类型。API key 存在钥匙串，不写进配置文件。
- **中转站能看到发过去的全部明文**，等于把 History 交给第三方。配置页要明确提示。
- **CLI 后端的限制**：
  - 每次调用要启动一个进程，慢，还要占订阅额度，不适合分钟级这种高频档，更适合小时级和每天的批处理；
  - 调用时关掉工具、只读沙箱、关闭 stdin、要求 JSON 输出，避免 History 里注入的指令让它执行操作；
  - 订阅账号能否这样自动化调用，要看 OpenAI / Anthropic 当前的使用条款，开工前核实；
  - 不直接读 `~/.codex/auth.json` 去调接口：格式随版本变，条款上也更模糊。

### 9.4 签名

macOS 的权限按签名身份授权。暂时没有 Apple 开发者账号：

- 自用：钥匙串里建一张固定的自签名代码签名证书，每次构建都用它签。**开工第一件事是实测重新构建后权限是否保留。**
- 他人从源码构建：安装脚本自动创建证书并签名。
- 下载发布版：首次打开要右键"打开"，每次更新都要重新授权。用户多了再买开发者账号做公证。

## 10. 技术栈

| 组件 | 选型 |
|---|---|

| 记录格式 | JSON Schema → 生成三端类型 |
| 向量检索 | v1 不做 |

## 11. 版本规划

### v1：只做 Mac，三层全部打通

- **采集端**：屏幕（AX 优先，OCR 兜底）、应用/窗口/URL、剪贴板、文件、日历、Agent 会话、浏览器历史、shell 钩子、git。
- **中枢**：接收、存储、密钥拦截；三档提炼，产出线程、项目、日记、当前状态；待确认列表（项目聚类、线程完成）。
- **网页**：History 时间线；简略/详细/证据三层；待确认；手动补写、删除、修正；保留天数设置和一键清理；暂停。
- **交给 Agent**：Claude Code、Codex 适配器（hook + MCP）、读取审计。

不做：音频、Android、微信、画像、向量检索、跨设备去重、中转信箱、公证发布。

### v2：音频

第 5 节全部内容（Mac 采集端自己转写），加声纹类待确认、跨设备去重。

### v3：Android

第 4.3 节，加本机转写、本机查看、配对、同步（含 9.1 的回传）、手机快捷补写入口。

### 之后

设备之间互相同步（在手机上看其他设备的记录）、微信插件、画像、向量检索、中转信箱、更多 Agent 和模型适配器、Windows 采集端或把中枢迁到 Windows。

### v1 开发顺序

| 步骤 | 内容 |
|---|---|
| 0. 实验 | 自签名证书重新构建后权限是否保留；AX 在常用应用上的覆盖率（浏览器、编辑器、终端、微信、飞书）；子进程是否继承采集端权限；SQLCipher + FTS5 + 中文分词在 Bun/Node 上能否一起用 |
| 1. 采集和查看 | 采集端、中枢接收、History 网页，不接大模型。先接无特殊权限的来源（Agent 会话、shell、git、浏览器），再接屏幕和剪贴板 |
| 2. 提炼 | 线程、项目、当前状态、日记，待确认列表 |
| 3. 交给 Agent | hook、MCP、审计 |

### v1 验收（每天用 1–2 周后）

- 抽查 History，大部分记录准确；
- 开新会话时需要交代的背景明显变少，Agent 没有被过时状态带偏；
- 故意放进几个假密钥，一个都没进数据库；
- 每天模型费用与估算相符；
- 采集端平均 CPU < 3%、内存 < 300MB。

## 12. 成本估算（未实测）

重度用户每天活跃 10 小时，去重压缩后进模型约 0.5–1M token/天。

|---|---|

| 小时级 Sonnet 5.5（$2 / $10，缓存命中 0.05×） | 约 $0.5/天 |

| 合计 | 约 $0.3–1/天 |
