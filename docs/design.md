# record-anything 设计文档

> 原始设计：2026-11-08；实现状态更新：2026-11-25。对外应用名 **Tacit**，包标识与数据目录沿用 `record-anything`。
> v1（Mac 采集、整理、时间线与 Agent 接入）、v2（Mac 音频转写）、v3（Android 录音与 HPKE 同步）以及星形同步、中转信箱与独立服务端中枢均已进入实现或验证阶段（详见 2.1 与 `docs/contracts.md` 第 6 节）。当前产品规则以 `AGENTS.md` 为准，接口以 `docs/contracts.md` 为准。
> 本文仍含部分远期规划项：三端类型自动生成、插件密钥配置与长期用户画像尚未实现；MCP 使用 stdio 转发本机/设备协议，常规整理每 15 分钟一轮。
> 第三方插件在 macOS 受系统沙箱限制，只读明确获准路径，隔离不可用时拒绝运行；内置来源仍以本机用户权限运行。黑名单覆盖主流密码管理器，隐私窗口标题识别的跨浏览器可靠性仍待进一步验证。

## 1. 定位

Tacit 把 AI 会话、聊天和录音整理成每天发生的事、用户的决定及可点回的原文。同一份整理结果面向两个出口。

| 出口 | 使用方式与验收目标 |
|---|---|
| 时间线 | 用户看一天的一句话概述和按时间排列的活动段，每段可展开原文。 |
| MCP 与会话带入 | Claude Code 和 Codex 可主动读取历史，也会在新会话带入当前项目的事项摘要。按利用率、命中率和准确率验收。 |

梳理时优先采用用户给 AI 的话、发出的消息、自己的声音和笔记，其次采用别人对用户说的话。屏幕和浏览器只提供应用、标题和时长，采集的正文可搜索。History 可浏览、搜索、删除、修正，派生结果可从 History 重建。

Tacit 面向个人使用，以 MIT 开源协议提供自部署。后台默认只监听本机。

## 2. 架构

```
 采集端（每台设备一个）                 中枢（Mac 本机或独立服务器）                  使用端
┌──────────────────────┐            ┌─────────────────────────────────┐        ┌──────────────────┐
│ Mac 菜单栏应用（Swift）│  加密批次   │ 接收 → 密钥拦截 → History 存储   │  hook  │ Claude Code      │
│ Android 应用（Kotlin） │ ─────────→ │        ↓                         │ ─────→ │ Codex            │
│ 外部插件（任意语言）   │  先存本地   │ 提炼：线程 / 项目 / 人 / 时间线 / │  MCP   │ 其他 AI（适配器） │
│                      │  能连再传   │       当前状态                   │        │                  │
│ 本地：VAD、声纹、转写、│            │        ↓                         │  客户端 │ Mac 原生窗口 /   │
│ 文本去重、黑名单       │            │ 设备协议 · MCP · 状态页（备用）   │ ─────→ │ Android / 状态页 │
└──────────────────────┘            └─────────────────────────────────┘        └──────────────────┘
```

**分工规则：采集端负责所有读取并持有系统权限；中枢只接收数据，不申请任何系统权限。**

- **每台设备转写自己录的音频**，中枢只接收文字、声纹向量和质量指标，不接收音频。唯一例外是待确认列表要播放的试听样本（见第 5 节）。
- **查看**：Mac 采集端自带原生窗口，Android 支持查看本机录音及（查看权限下）中枢整理的时间线，中枢网页仅作为本机模式下的备用状态页。多设备之间走星形同步，见 2.1。
- Mac 采集端和手机走同一套协议，对中枢来说只是又一台设备。
- 中枢可以独立部署在另一台 Mac 或 Linux/Docker 服务器上，采集端和协议保持一致。
- 避免给 Node/Python 解释器开"完全磁盘访问"这类全局权限。

### 2.1 星形同步与中枢拆分

规则见 `AGENTS.md`「设备与网络」。这里写结构和顺序。

**星形同步**：各端只把原始记录、删除和修正送到中枢。整理只在中枢做，整理结果只由中枢写，再推给其他设备，所以不会出现两边同时改、要合并冲突的情况。往下推的是整理结果（时间线、当天概述、项目概况、新会话会带入的内容）；原文在点开时按需向中枢取，私密内容不推。

**拆分后的角色**：

| 角色 | 放在哪 | 负责 |
|---|---|---|
| 中枢 | 一台 Mac，或用户自己的服务器 | 数据库、整理、模型调用、Agent 查询、设备管理 |
| 采集端 | 每台要记录的设备 | 系统权限、屏幕识字、转写和声纹（中枢不收音频）、待发送记录加密落盘 |
| 查看窗口 | 任意一台 Mac | 读中枢推下来的整理结果，原文点开再取 |
| AI 工具接入 | 写代码的那台机器 | 新会话带入读本机缓存（中枢连不上也能用），搜索和读原文实时问中枢 |

所有客户端都按第 6 节同一套设备协议连中枢，传输方式有局域网直连、任意 URL、中转信箱（`docs/contracts.md` 6.8）。中枢和客户端在同一台机器上时走本机快路，规则不变。

**现在 Mac 上要解开的耦合**（2026-11-23 读代码确认）：

- 采集端固定发往 `127.0.0.1`，令牌和端口从共享数据目录里的 `token`、`hub.json` 直接读（`collector/Sources/Collector/Hub.swift`）。
- 查看窗口用同一个全权限令牌读写中枢的管理接口（`collector/Sources/Collector/Viewer/HubAPI.swift`）。
- MCP 和新会话带入只连本机地址（`hub/src/agent-cli/client.ts`）。
- 日志、诊断信息、小组件快照都是两边直接读同一个数据目录。
- 数据库密钥、模型 API key、设备密钥都在这台 Mac 的钥匙串里。
- 中枢随应用包安装，由采集端负责登录自启。

**拆开要补的**：

- 设备权限分级：配对时定这台设备能做什么，分采集（只送自己的记录）、查看（读整理结果）、管理（改设置、填模型 key、删除任意记录）三级，代替现在的单一全权限令牌。远程删除和权限变更按删除、权限类改动的要求，先在测试环境看到真实运行结果。
- 中枢的密钥存放：中枢在 Mac 上继续用钥匙串，在服务器上另定存法。
- 诊断、日志和状态改从接口取，不再直接读共享目录。
- 中枢可以单独安装、单独启动。

**阶段与顺序**：每一步做完，单机用法照常可用。

1. 中转信箱（已实现，`docs/contracts.md` 6.8）：设备经信箱上传与配对，可自部署到 Cloudflare Workers 或 Docker。
2. 中枢下推整理结果（已实现，`docs/contracts.md` 6.9）：Mac 查看窗口与 Android 查看端按星形同步读整理结果，原文按需向中枢读取。
3. Mac 采集端和 AI 工具接入改走设备协议（已实现，`docs/contracts.md` 6.10）：同机走本机快路，AI 工具支持离线带入本机缓存。
4. 设备权限分级与中枢独立部署（服务端已实现，Mac 连接远端向导完善中，`docs/contracts.md` 6.11–6.12）：允许中枢单独装到另一台 Mac 或服务器上。

**核心取舍说明**：

- **下推变更用全局合并索引，不存正文拷贝**（6.9）：相比按设备复制整份结果，单张只存键的 `projection_changes` 合并表更契合“删除就是真删”——删原文时旧整理结果不会残留在多份队列里，离线多日也不重放中间态；`project_context` 由中枢预计算下推，保证项目页“正在推进的事”与新会话带入严格一致、避免 Swift/TS 两端逻辑漂移。
- **信箱下行先轮询 + 单条覆盖，暂不改信箱服务端**（6.9）：复用 v0.4.2 已上线的 `relay/`，每台查看设备的 `down` 最多保留 1 条未取推送（新变更替换旧条，删除时立即替换成无正文的 `projection.invalidate`），离线超 24 小时改为轻量 `hint`，防止撑爆 100 MiB 配额；查看端定时轮询远低于 20000 次/天限额，后续需要秒级远端刷新时再扩展设备级 `watch`。
- **同机快路保留完整 HPKE 走 loopback，不开局域网口**（6.10）：相比另写一套无加密 Unix Socket 协议，走 `127.0.0.1:<port>/v1/device` + 完整 HPKE（Apple Silicon 单次 < 0.3 ms）能让本地与远端共用同一套鉴权和权限代码；同时把本机绑定标记为 `local_only`，确保纯单机用户不会打开 `0.0.0.0:47824`。
- **AI 工具使用独立受限 `agent` 身份 + 800 ms 超时回退本机缓存**（6.10）：不复用 Mac 的 `admin` 设备私钥，守住“AI 工具不能删数据或改设置”的边界，且能在无 `Tacit.app` 的远程开发机上独立运行。SessionStart 钩子总超时 2 秒，直连 800 ms 拿不到或仅信箱可达时立即用本机 7 天内有效的 `project_context` 缓存，不阻塞开会话；MCP 搜索和读原文仍实时问中枢。
- **非 Mac 中枢采用“外挂根密钥 + 加密保险箱 `secrets.enc`”**（6.11）：相比全放环境变量或明文文件，只需在数据目录之外挂载一个只读根密钥文件（Docker secret / systemd credential），其余密钥加密存在 `secrets.enc`，既允许运行期远程改模型 Key 和动态换信箱，又保证备份数据目录不会顺带泄露密钥。
- **三级权限 + 禁止单步远程提权 + 远程删除限流**（6.11）：界面保持采集 / 查看 / 管理三级，防止配置复杂化；已有普通设备不能通过单个远程请求直接升为 `admin`，也不能远程移除最后一台 `admin`；远程删除默认每分钟 ≤ 200 条、24 小时 ≤ 1,000 条并记入 `security_audit`，控制密钥泄露或客户端异常的爆炸半径。

**已确认（2026-11-23 用户确认全部按推荐）**：

1. **`view` 设备按需读取 `private` 原文的边界**（补充 `AGENTS.md`「设备与网络」「隐私与删除」）：私密内容绝不下推已确认；建议默认 `view` 设备也**不能**按需取 `private` 原文，仅 `admin` 设备可按需读取且只在内存展示、不落盘。
2. **离线查看端的删除即时性边界**（补充 `AGENTS.md`「隐私与删除」）：在线设备会在秒级/下轮同步立即清除已删摘要与小组件，但离线设备在下次连上中枢前本地缓存仍暂时留有旧摘要（与已发给云端模型的内容、离线手机同理）。
3. **三级权限与独立 `agent` 身份的划分**（细化 2.1 三级权限与 `AGENTS.md` 受限令牌规则）：确认对外展示采集 / 查看 / 管理三级（`view` 包含本机采集能力，采集开关由本机数据源开关控制），而 AI 工具接入作为独立 `agent` 受限身份自动签发、不共用 `admin` 密钥。
4. **提权至 `admin` 的硬限制**：确认禁止远程单步把已有 `collect`/`view` 设备升为 `admin`（须通过中枢本机 CLI 或重发 5 分钟 `admin` 配对邀请），且禁止远程移除/降权最后一台 `admin`。
5. **远程删除限流熔断阈值**：确认远程 `admin` 删除默认上限（建议每分钟 200 条、每 24 小时 1,000 条，超限返回 429、大批量删除走中枢本机 CLI）。
6. **非 Mac 中枢的密钥存放方式与容器形态**（细化 `AGENTS.md`「安装与运维」第 4 条）：确认采用“数据目录外只读根密钥文件 + 数据目录内加密 `secrets.enc`”，以及用单容器（`tacit-hub run` 同管 `serve` 与 `distill`）作为服务端部署形态。
7. **历史 `device = "mac"` 记录不改写**（遵循 `AGENTS.md` “记录写入后不再修改”）：确认拆开后保留历史记录的 `device = "mac"` 原样不动，新采集记录改用 `mac-<8位base32>`，由 `admin` 权限统一管理删除和修正。
8. **独立中枢下的状态页入口**（补充 `AGENTS.md` “中枢状态放在中枢网页的状态页”）：独立中枢默认不再对外暴露网页端，建议本机单机模式保留原网页状态页，同时在 Mac 设置页内提供经设备协议 `status.get` 拉取的原生状态视图。
9. **多台 Mac 上同一仓库路径不同时的项目匹配**（扩展 4.7 `keys.repos`）：确认在项目 `keys` 中增加归一化 git remote（`remotes`），本机路径未命中时用于离线/跨机新会话带入的项目匹配。
10. **信箱下行第 2 步先轮询、暂不改 `relay/` 协议**：确认先由查看端定时轮询 `down`（前台 30 秒 / 后台 5 分钟），后续按实测延迟再决定是否为 `relay/` 增加设备级 `watch`。
11. **独立中枢时区策略**：确认独立部署须显式设置时区（`TZ` / `timezone`），未设置且落到 UTC 时在状态页与设置页告警。

## 3. History 记录

### 3.1 粒度

采集端的底层事件（每次界面变化、每个人声片段）**不进 History**，只在设备本地的临时缓冲里。写进 History 的是按规则合并后的**活动片段**：同一应用、同一上下文下连续的一段。Mac 上一天大约几百条，可以像浏览器历史一样一页页翻。

### 3.2 字段

```yaml
id:          01JC8...            # ULID，在设备上生成；离线可生成，重复上传自动去重
schema:      1                   # 格式版本
device:      mac-work
source:      mac.screen          # 来源插件，见第 4 节
kind:        span                # span（时段）| event（时刻）
t_start:     2026-11-19T14:02:10+08:00
t_end:       2026-11-19T14:27:45+08:00   # event 没有
t_received:  2026-11-19T14:28:01+08:00   # 中枢收到的时间，用于估算设备时钟偏差
context:                         # 按来源填有的字段
  app:       com.todesktop.cursor
  window:    export.ts — sunny-ledger
  url:       null
  repo:      ~/Projects/sunny-ledger
  cwd:       null
  chat:      null
  place:     null
people:      []                  # 指向"人"实体：说话人聚类 id、联系人
title:       Cursor · sunny-ledger · 25 分钟   # 简略版，一行；能用规则拼就不调模型
body:        |                   # 详细版：去重后的屏幕文字、带说话人的转写、消息列表
  ...
media:       []                  # 原始素材引用，每项带 expires，按保留天数清理
capture:     { method: ax, confidence: 0.95 }  # ax | ocr | asr | db | api | manual
sensitivity: normal              # normal | private | redacted
redactions:  0                   # 写入前被拦下的密钥数量（只记数量和类型）
dup_of:      null                # 重复记录指向代表记录
corrects:    null                # 修正记录指向被修正的那条
```

格式以一份 JSON Schema 为准；当前 TypeScript 与 Swift 生产方子集为手写，并用共享样例约束编解码与校验。三端类型自动生成仍是后续工程改进，尚未交付。

### 3.3 各来源怎么切成一条

| 来源 | 一条记录 | 切开条件 |
|---|---|---|
| 屏幕 | 同一应用、同一窗口/页面/仓库下的连续使用 | 切换上下文超过 15 秒，或空闲超过 2 分钟 |
| 音频 | 一段对话，正文是带说话人和时间戳的转写 | 静音超过 60 秒；展示与总结按间隔不超过 10 分钟归场 |
| 聊天 | 微信窗口单条消息（`mac.wechat`）或会话片段 | 整理切片按会话与间隔 30 分钟归段 |
| Agent 会话 | 一次会话的对话批次 | 会话安静满 3 分钟或批内最早消息满 15 分钟即上传；只保留用户输入和 AI 最终回复，丢掉工具输出 |
| 浏览器访问 | 同一站点的连续访问合并成一条 | 切换站点或间隔切开 |
| 手动补写 / 修正 | 用户写的一段话，或挂在原记录上的修正 | — |

### 3.4 规则

- **写入后不再修改。** 记录属于哪个项目、哪个线程，存在单独的归属表里。重新聚类、用户纠正都只改归属表。
- **修正**是一条新记录：`source: manual`，`corrects` 指向原记录。显示和提炼都以修正为准，原文折叠保留。手动记录的可信度最高，自动推断不能覆盖它。
- **删除就是真删**：删记录、原始素材、全文索引；引用过它的线程、项目、日记标记为待重新生成。同步来源（浏览器历史等）下次会把它再导进来，所以留一个只含 id 和内容哈希的墓碑，防止重新入库。已经发给云端模型的内容无法撤回。
- **跨来源重复**：每条都保留，选一条作代表，其余 `dup_of` 指向它。列表和提炼只用代表；误判了也不丢数据。
  - Mac 和手机录到同一段对话：按校正后的时间重叠和转写相似度判断，按采集端随记录附上的质量指标（有效人声时长、音量、转写置信度）保留更好的一份。中枢没有音频，只比文字和指标。
  - 同一条微信消息来自手机通知和 Mac 数据库：按会话、发送人、内容、时间匹配，以数据库那份为代表。
- **时间**一律带时区。同步时估算各设备和中枢的时钟偏差，跨设备去重用校正后的时间。
- **人**是单独的实体。声纹聚类、微信联系人、电话号码在待确认列表里确认后才合并成同一个人；确认后按 id 回填，历史记录里的"说话人 B"全部显示成真名。

## 4. 数据源

### 4.1 Mac（v1）

| 来源 | 做法 | 权限 |
|---|---|---|
| 屏幕文字 | 切应用/窗口/标题/URL 时读当前窗口的辅助功能（AX）树；使用中每隔几秒检查一次变化。和上次比对，只保留新增文字。空闲用系统"距上次输入秒数"判断，不监听键盘 | 辅助功能 |
| Electron / Chromium | 每个应用只设置一次 `AXManualAccessibility`，反复设置会让前台卡顿 | 同上 |
| 终端 | 只取可见区域的变化，不读整个回滚缓冲 | 同上 |
| 应用、窗口、URL | NSWorkspace + AX；URL 读地址栏，或 AppleScript 读 Safari/Chrome | 辅助功能 |
| Agent 会话 | 增量读 `~/.claude/projects/**/*.jsonl`、`~/.codex/sessions/**`（含归档后的 `.jsonl.zst`）；只留用户输入和最终回复；按 cwd 对应到仓库 | 无 |
| 浏览器历史 | 复制 Chrome / Arc / Safari 的 History 库后增量读 | 完全磁盘访问（Safari） |
| OCR（v1） | AX 读不到或正文过少时截图交给 Apple Vision（实测需要：微信、Zed），图只在内存里，用完即丢 | 录屏（可选；不开时这些应用只记应用名和窗口标题） |
| 微信对话（默认关闭） | 开启后读窗口：在 OCR 上把聊天区按位置拆成一条条消息（见 4.5）；不解密本地聊天库。支持导入标准导出格式（如 JSON / ChatLab）补历史（规划中） | 录屏（OCR） |

剪贴板、文件、日历、shell 钩子和 git 等早期实验来源已移除，已有历史记录保留可搜索。

AX 扫描约束：
- 只能读到当前桌面（Space）上的窗口，所以只读前台应用的 `AXFocusedWindow`，不做后台全量扫描。
- 每次扫描设元素数和时间上限（3,000 个元素、200 ms、深度 60），只遍历与窗口可见区域相交的元素，避免超大视图（如大型邮件列表）阻塞主流程。
- 每个元素用一次 `AXUIElementCopyMultipleAttributeValues` 批量取角色、子节点、位置、尺寸，比逐个属性取快一到三倍；同层子节点按面积从大到小访问，输出再按文档顺序排。多数常见应用在 50 ms 内读完、无截断；部分 Electron 应用的树深超过 40 层。
- OCR（Vision，accurate，中英）预热后单次识别约 0.2–0.5 s；同一段至少隔 15 秒才再识别；识别出的文字和上次一样就把间隔加倍，最长 2 分钟，文字一变回到 15 秒。用到 OCR 的段整段标 `ocr`、置信度 0.7。

不做：Mac 相册、iMessage。

**插件**：调用系统接口的来源是 Swift 内置插件；读文件/数据库的来源是外部插件，任何语言都能写，由采集端启动，每行向 stdout 输出一条 JSON 记录。详见 4.4。

### 4.3 Android（v3）

只用普通侧载权限：不写输入法、不 root，Shizuku 不作默认。

只收必要内容：

| 来源 | 做法 |
|---|---|
| 音频 | 前台服务录音，只留有“我”声音的对话；不录系统声音、不做日历会议例外；微信语音/电话时麦克风被占用，录不到 |

不做：聊天通知、应用使用（仅能反映单侧通知或打开时长，无法说明实际内容）、屏幕正文、短信、通话记录、照片、文件、位置、日历、剪贴板（Android 10 起后台不可读）以及手机端的跨来源整理。手机端可选开启单场对话的 AI 总结，查看权限下也可同步浏览中枢整理的各来源时间线。通话录音导入后续再评估。

应用内能查看本机采集的记录，存在本地加密库里；离线时也靠这个库攒数据，能连上中枢再传。

首次安装只要麦克风权限；部分定制 Android 系统（如 HyperOS）需要开启自启动、电量“无限制”和多任务锁定，设置里的“后台运行”逐项检查可验证状态并引导跳转。系统升级可能重置保活设置，应用应能发现服务被停并提示。

### 4.4 插件与处理器（2026-11-10 定）

数据源和处理器都做成插件。现有的屏幕、录音、Agent 会话、浏览器先迁成内置插件（剪贴板、文件、日历、shell、git 2026-11-22 删除），接口和第三方插件相同。

**清单**（插件目录里的 `plugin.json`）：

| 字段 | 说明 |
|---|---|
| id、名称、版本、作者 | id 全局唯一，记录的 `source` 用它 |
| 平台 | macOS / Android / 两者；不支持的平台不显示 |
| 运行方式 | 定时拉取（间隔）、持续监听、手动导入（选文件） |
| 权限 | 辅助功能、录屏、日历、某些目录、网络等；安装时列给用户确认 |
| 配置项 | 类型（文本、数字、开关、目录、选项、密钥）、默认值、说明；设置页按这里自动生成表单，密钥类进钥匙串 |
| 历史 | 能否导入启用前的历史，最早能到哪天 |
| 记录格式版本 | 和中枢的 History 格式版本对不上就拒绝启用 |

**运行**：
- 外部插件是独立进程，由采集端启动，stdin/stdout 走 JSON 行协议：宿主下发配置和上次读到的位置，插件输出记录、进度、错误、新的位置。增量位置由宿主保存，插件本身不存状态。
- 插件只产出记录。入库前统一经过黑名单、密钥拦截、格式校验，和内置来源走同一条路，插件绕不过去。
- 内置来源继承采集端的系统权限（实验 0 已验证辅助功能）。第三方插件使用 macOS Seatbelt 隔离：默认拒绝，允许读取安装快照、只读游标和确认的输入路径；网络、写入和子进程拒绝。不支持的平台或缺少隔离工具时拒绝执行，详见 plugins.md。
- 状态页显示每个插件的健康状况：上次运行、产出条数、最近错误、是否被自动停用（连续失败）。

**安装与卸载**：
- 从本地目录或 git 地址安装（git 地址装到数据目录的 `plugins/` 下，记下提交号，更新时显示改了什么）。
- 安装时列出插件声明的权限，用户确认后装上，默认停用。
- 卸载时问用户：保留它产生的记录，还是按删除流程真删（连带重新生成提炼结果）。

**处理器**（对已采到的素材做加工，可以换引擎）：

| 处理器 | 可选引擎 |
|---|---|
| 转写 | 本地 SenseVoice（默认）、本地 Whisper 系、Apple 设备端识别、云端转写服务（用户自己开、自己填地址和 key） |
| 说话人识别 | 本地声纹模型（三端必须一致，见第 5 节） |
| OCR | Apple Vision（默认），以后可加本地模型 |
| 提炼模型 | 见 9.3，另加本地预设：Ollama、LM Studio 走 OpenAI 兼容接口，自动列出本机已有的模型 |

- 云端转写：默认不开。开了以后这台设备要转写的音频直接发给用户填的服务，中枢仍然不收音频；设置页写明音频会离开设备、发给谁。
- 本地模型处理 `private`：默认关。打开后 `private` 内容只交给配成本地模型的档位提炼，云端档位仍然拿不到；提炼结果照样不进自动注入。
- Agent 适配器（Claude Code、Codex 之外的 Cursor、Gemini CLI 等）也按适配器接，后续按需扩展。

### 4.5 微信对话采集

**不解密本地聊天库**：本项目以 MIT 协议开源，不涉及任何进程内存读取、二进制重签名或本地加密数据库解密。

**窗口识字（OCR）**：macOS 微信 4.x 采用自绘界面，辅助功能（AX）树仅能暴露极少元素；因此“微信对话”数据源（默认关闭）基于 Apple Vision OCR，按版面坐标拆分聊天区的消息结构（实现见 `CollectorCore/WeChatLayout.swift`）：

- 聊天区靠右的气泡为自己发出，靠左为对方；群聊中气泡上方的小字为发送人昵称，同一人连续发言往前继承；居中短行为时间分隔；过滤图片内极小字号噪声。
- 会话名取聊天区顶部标题，窗口标题不可用时由 OCR 识别。
- 每条消息按（会话、发送人、内容、最近时间分隔）计算指纹去重，切换会话与上下滚动不重复入库。
- 仅记录在屏幕上浏览过的消息；图片、语音仅记占位（`[图片]`、`[语音]`）。

**导入**：后续可支持导入微信导出工具产出的 JSON / ChatLab 标准格式文件，并沿用相同指纹与窗口采集记录去重。

## 5. 音频流程（v2）

```
采集端：人声检测（VAD） → 切成对话 → 声纹判断有没有"我" → 转写 → 对话内说话人区分 → 加密同步（文字 + 声纹向量 + 质量指标）
中枢：  跨对话说话人聚类 → 匹配声纹库 → 跨设备去重 → History 记录
```

| 步骤 | 位置 | 说明 |
|---|---|---|
| VAD | 采集端 | Silero VAD，没人说话的部分当场丢掉 |
| 切成对话 | 采集端 | 人声间隔不到 60 秒算同一段 |
| 声纹判断 | 采集端 | sherpa-onnx 声纹模型，按**整段对话**判断有没有用户；没有就不转写、不离开设备、不留记录。用户的声纹样本由中枢下发 |
| 转写 | 采集端 | 本地 SenseVoice（sherpa-onnx）。Android 用高通 QNN 调 NPU，不支持时回退 CPU；模型运行时下载并校验，不打进安装包。引擎可换，云端转写要用户自己开启（见 4.4） |
| 对话内说话人区分 | 采集端 | 需要音频，只能在录音的设备上做；每个说话人每 3 秒连续窗口算一个声纹向量，随转写上传 |
| 跨对话聚类、声纹库 | 中枢 | 只用上传的向量 |
| 跨设备去重 | 中枢 | 见 3.4 |

例外和规则：
- **即使没有用户声音也保留**：Mac 上会议软件正在用麦克风（应对"一句话没说的会议"）。日历有会的例外 2026-11-22 随日历来源撤下。
- Mac 两路录音按整段对话判断：麦克风那路有用户就转写整段。系统声音那路只在开会时转写，其他时候只用来去回声（避免把音乐、视频写进 History）。
- **试听样本**：这是唯一上传到中枢的音频。目前默认只分“我”和“对方”，不再把每个他人声音送进待确认列表（2026-11-16 收敛；未确认的他人声音在相关录音全部过期后连声纹一并清理，2026-11-20）。仅在确认“我”的声音（或处理历史已存在的声音待确认项）时，采集端从还在保留期内的音频里截取样本（每个说话人不超过 3 段、每段约 10 秒），标注后删除，只留声纹特征。
- 用户的声纹不需要注册，只需在时间线顶部的提示里从样本中标出一次“这是我”。确认过的“我”的声纹向量下发给各采集端，用于上面的声纹判断。
- 用户在用 Mac、两台设备在同一网络时，手机暂停录音。
- 原始音频只留在录音的设备上，按保留天数清理（Opus 约 7MB/小时）。用户开了云端转写时，要转写的音频会发给用户填的服务，其余不变。

三端必须用**同一个声纹模型**，否则声纹无法互相比对。

## 6. 提炼层

### 6.1 对象

| 对象 | 是什么 |
|---|---|
| 线程 | 一件连贯的事，可横跨多台设备和多个来源 |
| 项目 | 一组线程的长期归属：代码按仓库，其他按主题或人 |
| 人 | 联系人和声纹聚类合并成的同一个人 |
| 时间线 | 本地自然日的当天概述和活动段（同时进行的几件事各成一段，可交叠）。段含起止、实际覆盖时长及原始记录 ID |
| 画像（规划中） | 长期偏好、习惯、常联系的人、作息；每条附证据，可删可改；尚未实现 |
| 当前状态 | 从活跃线程投影出的"此刻在做什么"，即注入给 Agent 的 now.md |

### 6.2 三层内容

给 Agent 的事项和项目采用三层内容：

| 层 | 给谁 | 内容 |
|---|---|---|
| 简略 | Agent 自动带入，用户可在项目页查看实际会带入的内容 | 一两句：在做什么、做到哪 |
| 详细 | 点开才看；Agent 按需读 | 目标、已定（附原因和生效时间）、被否决的方案、未决、下一步、相关文件/链接/命令/人、关键原话 |
| 证据 | 核对、纠错时 | 指回 History 原始记录 |

规则：
- **先写详细版，简略版只从详细版派生**，简略版里每句话都能在详细版找到出处。
- "已定"和"推测"分开写；推测要标依据和置信度。
- 决定被推翻时，旧条目标记失效并注明被哪条取代，不删除（双时态：事实何时成立 / 系统何时得知）。
- 每个对象带更新时间和置信度，Agent 能判断是否过时。
- 项目、线程的显著度按新近度和频率衰减（参考 Mylyn 的兴趣模型）。

### 6.3 处理节奏

全部异步；Mac 睡眠期间积压的数据醒来后补跑。

只有一个整点钟（2026-11-20）：快步骤每 15 分钟跑；每小时到点后按下表顺序把慢步骤和时间线一起跑完，失败的部分 15 分钟后随下一轮重试。

| 节奏 | 默认模型 | 做什么 |
|---|---|---|
| 每 15 分钟 | Haiku 5.5 | 切片段（不调用模型）；写结束满 10 分钟的录音总结；新记录归入已有线程，或提议新线程；判断工作或生活、所属项目；处理被打开或被 Agent 读取的待更新线程详细版；线程暂停与归档、更新“此刻”（不调用模型） |
| 每 15 分钟，快步骤之后 | 每天那档 | 默认批量润色今天已安静满 30 分钟的草稿段，每批只取这些段的原文和最近五段已润色的标题、描述。迟到记录或修正改变成员时重润色受影响的段。可在 AI 模型设置改为每小时或只在晚上 |
| 每小时，按顺序 | Sonnet 5.5 | 合并重复线程（每天一次）；待更新事项的详细版（只送新片段）和简略版；项目状态；新项目、新说话人进待确认 |
| 每小时，慢步骤之后 | 每天那档 | 若设为每小时润色，先补已结束的草稿。当天概述只读已润色段的标题、描述和项目名，内容变化才调用；概述也可设为每 3 小时或只在晚上 |
| 跨天后的整点 | 每天那档 | 对标记待整理的历史日期做一次全天收尾，处理相邻段合并和 30 段上限；只在晚上的润色和概述在这轮写入 |
| 打开今天的时间线 | 每天那档 | 超过 30 分钟且有草稿时可排一次增量润色和概述检查，尊重只在晚上的设置。排队后今天已被写过则跳过 |

模型只是默认推荐，每一档用哪个模型由用户配置（见 9.3）；未配置 `models.json` 时代码默认使用本机已登录的 `claude-cli`（haiku / sonnet）。

AI 模型设置的“时间线整理”里可以选择润色和概述的节奏，并设置每天用量上限，默认不限。用量按模型报回的输入和输出 token 计；达到上限后从下一次整理调用起暂停，手动整理保留排队，草稿继续实时出现，连接测试照常可用。暂停在本地次日 0 点恢复，调高上限到高于已用量或改为不限也可解除。设置显示最近七个本地自然日的日均用量、其中时间线的日均用量和今天已用量。日均按有 token 数据的天数计算。

只有屏幕、浏览器、应用记录的片段可以并进已有线程或候选，不能单独发起新线程（2026-11-18）。

**归属线程的顺序**：先用确定线索（仓库/cwd、聊天对象、URL、人）→ 文本相似度 → 交给模型 → 模型置信度低的进待确认。

**门槛**（起始值）：
- 累计 15 分钟活动，或跨两次以上会话，才建线程；不够的只进日记。刷视频、零碎查资料只留在 History 和日记。
- 2 小时没有新记录：线程标为暂停，仍按日历时间。
- 事项满 `archive_days` 个使用天没有新活动后进入 `archived`，仍可查询。既有未答的完成确认过期。
- 使用天是 `records` 表中至少有一条记录的中枢本地自然日。归档计算从最后活动的次日起，只统计截至当前时刻的记录。

### 6.4 待确认列表

Mac 时间线有待回答的问题时出现提示，展开后在原处处理，回答最后一项后提示消失。不弹通知。

| 类型 | 用户看到 | 操作 |
|---|---|---|
| 已存在的声音问题 | 2–3 段样本，可播放 | 填名字 / 就是我 / 与某人是同一人 / 忽略 |
| 新项目 | 候选名称和依据（哪些应用、对话、文件） | 新建 / 并入已有项目 / 改名 / 不是项目 |
| 合并建议 | 两个项目可能是同一个 | 合并 / 保持分开 |

**不确认不阻塞**：先用临时标签（"说话人 A""未命名项目：xx"）往下处理，Agent 读到时带"未确认"标记；确认后按 id 回填。

移除项目与对候选项目选择“不是项目”使用同一规则。保留原始记录和事项，解除项目归属和候选归属，撤下相关派生内容并关闭相关待确认项。原项目的仓库、站点和聊天键在本机持续忽略，后续自动识别跳过这些键。

### 6.5 Mac 主窗口

侧栏是时间线、搜索、项目列表，底部是记录状态、暂停和设置。时间线默认显示今天，时间轴与列表取同一批段，点段就地展开。用户可从页脚打开当日完整原始记录，旧日期的原始记录也照常可读。搜索按天呈现匹配的段和原始记录，点结果定位到段或原始记录。

有逐条时刻的聊天消息（非时间骨架来源、带聊天标识、起止相同）按每条前后各 2 分钟的并集计在场时间，裁在当天与活动段边界内；这些窗口先参与优先级裁决，被更高优先级活动占用的时间不重复计。录音仍按实际时长计。

AI 会话按含真实用户输入的批次实际起止计在场时间，每条输入最多支持 30 分钟；批次跨度在输入数乘 30 分钟以内时保留实际区间，超限从可定位的输入时刻（无逐条时刻时用批次起点）分配上限。没有任何用户发言的后续批次是上一轮的回复，在发起段剩余的输入上限内接着计时。当前采集格式只有批次首末时间，不据此虚构逐消息时间；若有逐消息时刻，按用户输入到下一输入或该轮回复结束计，单轮同样上限 30 分钟。评测与发布检查会话按专用来源标记排除，不计时、不参与摘要，原文保留可搜索；与 Agent 指标共用默认排除工具集合。机器目标续跑、自动任务和上下文交接不计时。自动产出归入当天同会话或同事项的用户发起段，无法归入时可保留零时长结果，时间轴不画条、摘要不采用。一天主线由用户在场时间和结果共同决定，可综合同项目多段。

每日整理最多向模型提供 50 个候选，正文仍最多 30 段。相邻的同事项段（同一线程；无线程时同一会话或聊天），间隔不超过 30 分钟且合并后实际证据覆盖至少 60% 时，无论是否超限都合并：候选阶段先合并，输出后再次兜底，不额外调用模型。被其他活动占用的时间不补计。兜底标题取在场较长段，描述以该段为先，另一描述不同时接在后面，整体不超过两句；依据、原文 ID、来源和应用取并集。合并后仍超限则按项目代表和实际覆盖时长取舍。省略只允许 request_only（只有请求、同意或催促且没有结果）、empty（没有具体内容，只证明采集存在）、excluded_session（评测或发布检查）。完成改动、原因或发现、验证或复现结果、学习中答对或弄懂的具体点、本人明确判断或决定、明确阻碍必须写入正文。内部 omissions 为每个省略提供 activity、reason、title、description、refs；无效或缺失理由按结果段处理，采用模型已给文字并校验本段引用；缺少有效文字则保留在未入时间线，并在运行记录警告。不额外调用模型，不用采集占位补文。

时间线只展示有具体行动、结果或明确判断、决定的段，单纯同意、确认继续、催促、授权安装同属纯请求。纯请求只作为后续结果的上下文，没有结果则省略；不把请求擅自改写成决定。没有具体内容的录音同样省略。不用“有会话记录”补齐模型省略的内容。未入正文的原文仍可查询。来源图标仅表示文字实际引用的来源，主时间轴不再叠加背景来源泳道；来源轨道仍可在全部记录中查看。

日期下方是当天概述。概述用 2–4 句、合计最多 160 字。从有在场时间且有具体结果或明确判断的段中选最多四条主线，支持跨项目，也包含聊天、录音中的工作沟通和生活活动。第一句点明主要活动，有项目时写项目的原名，无项目时写事情本身。每条主线交代功能、文档、地点或版本等具体对象，以及结果或停在哪。涉及他人时沿用相关记录中的称呼或聊天名，省去身份不明的编号。概述用“你”或省略主语，省去过程数字、给 AI 的操作指令、建议和核实状态。模型引用 1–4 个支撑概述的活动段，无合适内容时返回空值。缺少有效概述引用时，用在场活动段的标题兜底。已有摘要不做批量重算。

活动列表用连续细轴和起止时间呈现，展开原文时保持同一时间列。沿用暖灰和铜绿，不逐条画表格分隔线，不恢复按来源铺满的彩色总览。

项目页给用户读“这个项目现在怎么样了”，从上到下依次为：项目一句话概况（取已有项目简略版）；“正在推进”列出当前新会话会带入的事项（标题、一句话和最多 2 条未决），点开原地按时间正序读这件事跨天的经过，并可进入“AI 记住的要点”做事实纠错，组尾说明这几件会带入新会话；“最近的进展”按日期倒序列出该项目的活动段，沿用时间线简约档样式并可加载更早日期。串联只依据已有事项归属，不凭相似标题猜测，也不发起额外模型调用。

## 7. 交给 Agent

### 7.1 方式

- **会话开始时自动带入**：SessionStart hook 带当前目录问后台，在 **800 估算 token** 的默认预算内带入匹配项目的事项简略版，附一行可用工具提示，可在设置中调整预算。会话压缩后重新带入。
  - Claude Code：hook 输出 `hookSpecificOutput.additionalContext`（必须嵌套，放顶层会被丢弃）；写在用户级 settings，不走插件（插件 hook 有已知 bug）。
  - Codex：SessionStart hook（配置于 `~/.codex/hooks.json`，新 hook 需用户在 Codex 中批准一次）。
- **MCP（stdio，以读取为主）**：两边配置里只写一条命令（`bun …/hub/src/cli.ts mcp`），进程自己读数据目录里的受限凭据再调用中枢，令牌不出现在任何配置文件里。读取逻辑和审计都在 hub 里，MCP 进程只做转发。
  - `now()`：当前状态
  - `get(id, level)`：读线程、项目、人、日记；`level` = `brief` | `detail` | `evidence`，Agent 自己选读几层
  - `search(query, time_range)`
  - `timeline(range, device)`
  - 返回结果分页，控制单次大小。
  - `history_append(title, body, source_ref?, …)`：唯一的写入工具，见下。
- **Agent 只有一个追加工具**：它的会话本身就是数据源，会被自动采进来，纠错在客户端界面进行。唯一例外是用户明确要求"把这些存进来"（Notion 页面、自己整理的内容）时，用 `history_append` 往 History 追加：只追加、不改不删；同一外部条目重复写入去重，内容变了挂修正记录；写入前拦密钥；审计标注是哪个 Agent 写的。Codex 里这个工具每次都要用户确认。
- **审计**：Agent 每次读了什么都会写入审计表，可在设置的“维护 › 运行记录”中查看。

### 7.2 范围

- 只带当前项目中进行中的事项和近 3 天内有活动的暂停事项；没有识别出项目时留空。生活类内容由 Agent 主动查询。
- private 内容不自动注入，Agent 主动查询时可以拿到。

### 7.3 适配器

接入的 AI 工具做成**适配器**，按工具实际能力分别接入会话记录（作为数据源）与上下文查询（hook / MCP 注册）。Claude Code 和 Codex 支持会话采集、hook 和 MCP；Claude Desktop 通过本机 MCP 查询记录，不注册 hook，不采集聊天记录。其他工具等实际用到再扩展。（2026-11-12）

安装命令（如 `ra agents install`）在写入 `~/.claude/settings.json`、`~/.codex/config.toml` 之前先展示改动；`uninstall` 原样撤销。

### 7.4 与 AGENTS.md / 记忆文件的边界

`AGENTS.md` 管"怎么做"，由人维护；本系统管"发生了什么"，由机器维护。系统可以**建议**把某条已定的事写进 `AGENTS.md`，但不自己写。

## 8. 隐私与安全

按"越早拦越好"分五道关：

1. **采集前不采**：密码管理器、钥匙串、银行、浏览器隐私窗口进黑名单；安全输入框跳过；菜单栏可以随时暂停（1 小时 / 到明天 / 继续），Mac 上有全局快捷键。暂停期间 History 只记一条"已暂停"。
2. **写入前拦密钥**：本地规则识别 API key、令牌、私钥、JWT（参考 gitleaks）+ 高熵字符串检测，替换成 `[已脱敏:类型]`。**密钥从不落盘**，Agent 和界面看到的也是脱敏后的内容。有本地记录库的采集端（Android）写库前也要拦，和中枢用同一份规则。
3. **发云端前**：private 不进提炼（用户打开"本地模型可以处理 private"后，只有本地模型档位能拿到，见 4.4）。人名假名化可选，默认关（按待确认列表确认过的名单替换，结果回本地还原）。
4. **本地存储**：数据库和原始素材加密（SQLCipher / AES-GCM），Mac 密钥存放在钥匙串，Android 本地记录库密钥存放在 Android Keystore。Mac 上为避免自签名重装反复弹窗，数据库与音频密钥经 `/usr/bin/security` 读写，同用户下其他本机进程原则上也能调用该命令行工具读取——它提供的是静态落盘加密与操作门槛，而非针对本机同用户恶意程序的权限隔离。
5. **Agent 读取（防提示注入）**：History 里存的是不可信文本（网页、聊天、邮件）。当 Agent 以自动批准或较低确认门槛的模式运行时，被注入的指令可能被直接执行。
   - 提炼模型只写事实，遇到祈使句式内容改写成"某页面中包含一段指令"；
   - MCP 返回原文时标注来源，并说明这是数据、不是指令；
   - 自动注入只给简略版，尽量短。

**他人的声音与录音合规**：默认只保留有用户参与的对话（加上会议例外），旁人闲聊、电视声音直接丢弃。用户开启持续录音与会议转写时，应自行遵守当地法律法规并提前告知对话方。

**敏感级别**：
- `normal`：正常处理。
- `private`：不进提炼（可选让本地模型处理，见 4.4）、不进自动注入，Agent 主动查询时可以拿到（注意：Agent 读到的内容会发到其厂商的云端）。
- `redacted`：已脱敏。

## 9. 网络、同步与部署

### 9.1 网络

不依赖 Tailscale 或任何特定网络：

- **安全在应用层**：配对时 Mac 显示二维码（地址、公钥、一次性令牌），手机扫码；之后每批数据用 HPKE（RFC 9180）加密。
- **先存本地，能连再传**：手机可以攒几天数据。
- **中枢回传给设备的**（从配对起就要有，不等多端同步）：删除和修正，保证中枢删掉的记录在设备本地库里也删掉，设备上删的中枢也删；确认过的"我"的声纹向量；试听样本请求。
- **传输方式**：
  - 局域网直连（默认，Bonjour 自动发现）；
  - 任意可访问的 URL（Tailscale、WireGuard、反向代理、Cloudflare Tunnel 都行，由用户选）；
  - 中转信箱：只转交加密信封，Mac 醒来再取，配对也可以经它完成。可用仓库中的 `relay/` 自部署到 Cloudflare Workers 或 Docker，也可以关闭；换信箱不用重新配对。协议见 `docs/contracts.md` 6.8。S3、WebDAV 这类存储型信箱排在最后。
- **中枢默认只监听 localhost**（网页、MCP）；配对设备后才开放局域网接收端口。

### 9.2 安装与目录

- 从源码安装：一个脚本完成创建自签名证书 → 构建并签名采集端 → 安装中枢为 launchd 服务 → 打开引导页。
- 数据目录：`~/Library/Application Support/record-anything/`。
- 备份 = 加密的数据库文件 + 钥匙串里的密钥。**丢了密钥就丢了数据**，用 `bun hub/src/cli.ts keys export` 导出恢复命令，状态页和安装结束时提示。
- 升级时做 schema 迁移，迁移前自动备份。
- 卸载：移除 launchd 服务、Agent hook 和 MCP 注册，数据是否删除由用户选。
- 不收集任何遥测。

### 9.3 模型配置

模型提供方做成适配器，v1 支持三类：

| 类型 | 说明 |
|---|---|
| **API** | Anthropic 接口、OpenAI 兼容接口（可接 DeepSeek、豆包、本地 Ollama 等） |
| **中转站** | 同上两种接口，填自定义 base URL + key，支持把系统里的模型名映射成中转站的模型名 |
| **账号登录（CLI 后端）** | 调用本机已登录的 CLI：`codex exec` 走 ChatGPT 账号登录，`claude -p` 走 Claude 账号登录。不自己保存或复用它们的令牌 |

- 分钟、小时、每天三档分别配置模型，每档可以选不同类型。API key 存在钥匙串，不写进配置文件。
- **中转站能看到发过去的全部明文**，等于把 History 交给第三方。配置页要明确提示。
- **CLI 后端的限制**：
  - 每次调用要启动一个进程，慢，还要占订阅额度，不适合分钟级这种高频档，更适合小时级和每天的批处理；
  - 调用时关掉工具、只读沙箱、关闭 stdin、要求 JSON 输出，避免 History 里注入的指令让它执行操作；
  - 使用订阅账号经 CLI 自动化调用时，请自行遵守各模型服务商的使用条款；如用于高频或服务端部署，建议使用官方 API Key；
  - 不直接读取外部 CLI 的本地认证令牌文件去直接请求接口。

### 9.4 签名

macOS 的权限按签名身份授权。目前安装包未经过 Apple 公证：

- 发布版：始终使用同一张固定自签名代码签名证书签名；用户首次打开在 **系统设置 › 隐私与安全性** 放行一次后，后续升级沿用同一证书，已授予的系统权限可保留。
- 从源码构建：`./install.sh` 自动准备或复用本机自签名证书并签名。

### 双出口验收口径

| 项 | 验收方法 |
|---|---|
| 时间线 | 抽样检查多个使用日并逐段核对依据原文，确认描述准确且未遗漏当天主要活动，比例 ≥ 90%。 |
| 利用率 | 用 `scripts/agent-metrics.ts` 统计自动带入后发生主动查询的会话比例（排除评测与发布检查工具调用），作观察指标。 |
| 命中率 | 搜索空结果比例只作观察；验收时逐条核对空结果搜索，记录中存在相关内容却未命中的漏找比例 ≤ 1/10。 |
| 准确率 | 每次验收使用新日期数据构造 24 题，不复用调优题集，得分 ≥ 18/24；同时记录带入摘要延迟与人工纠错次数。 |
| 成本 | 按正常使用日模型用量与所用服务商价格折算，关注异常波动或失控重复调用。 |
| 采集端开销 | 按下列分状态口径统计（可用 `scripts/performance-sample.py` 采样）。 |

- 没人用（键鼠空闲满 5 分钟）的时段，采集端自身平均 CPU 低于单核 0.5%。
- 有人用的时段，采集端自身平均 CPU 低于单核 3%。
- 转写进程（`ra-audio-worker`）不计入上两项，按每小时音频耗用的 CPU 秒单独报告。
- 采集端内存按 95 分位统计，目标低于 300 MB；峰值和转写进程峰值单独报告。
- 由采集端引起的 `coreaudiod` 等系统进程开销单独报告。

## 12. 成本估算（参考量级）

重度用户每天活跃约 10 小时，去重压缩后送入整理模型的输入约 0.5–1M token/天；实际费用完全取决于所选模型、缓存命中率以及设置里的润色/概述频率，也可通过“每日 token 用量上限”硬性封顶。本地语音转写不产生云端费用。
