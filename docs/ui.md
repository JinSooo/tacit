# 界面规范

Mac 客户端和中枢网页共用这一套。改界面前先读，改完对照第 6 节自查。

## 1. 用词

界面只用左列的词，右列是代码和设计文档里的内部叫法。

| 界面用词 | 内部叫法 | 说明 |
| --- | --- | --- |
| 历史记录 | History、records | 侧栏、搜索框、"打开历史记录" |
| 事项 | thread、线程 | 一件在做的事，如"修复登录页" |
| 项目 | project | 不变 |
| 整理 / 更新 | 提炼、distill | "6 分钟前更新"；维护页的"整理启用前的历史" |
| 后台服务 | 中枢、hub | 设置分组、状态页 |
| 网页版 | 中枢网页 | |
| 自动带入 | 注入、inject | "新会话开始时带入" |
| AI 工具 | Agent | Claude Code、Codex 等 |
| 实时整理 / 每小时汇总 / 每日回顾 | 分钟档 / 小时档 / 天档 | Mac 模型界面的整理任务 |
| 回顾 | 日记、days | Mac 主窗口和维护入口 |
| 截图识字 | OCR 兜底 | 数据源名 |
| 提供商 | provider | 模型设置 |
| 依据 | evidence、证据 | 事实背后的原始记录 |
| 补写 | manual.note | 用户手动添加的记录 |

同一个动作只用一个动词：打开、添加、删除、修正、同步、导入、整理、连接、断开、暂停、继续、导出。不用"立即""马上"催促。

## 2. 颜色

一页只有一个强调色：铜绿。错误和需要处理的状态用胭脂，只染文字和小图标，不铺大面积红底。灰全部是暖灰。

| 名称 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| accent 铜绿 | `#3B7468` | `#7DB8A9` | 选中、主按钮、链接、当前位置 |
| on-accent | `#FFFFFF` | `#181716` | 强调色上的文字 |
| attention 胭脂 | `#9D2933` | `#E58A8F` | 错误、缺权限、录音中 |
| ink | `#1C1B1A` | `#F2EFEA` | 正文 |
| muted | `#6E6860` | `#A8A197` | 次要文字（对比度 ≥ 4.5） |
| faint | `#A39D94` | `#5E5953` | 只用于图形和分隔，不用于文字 |
| line | `#E7E3DC` | `#2F2C29` | 分割线 |
| paper | `#FBFAF7` | `#181716` | 页面底色 |
| raised | `#FFFFFF` | `#211F1D` | 分组底色 |
| fill | ink 5% | ink 6% | 时间轴轨道、输入框、悬停 |

状态正常不上色，只有出问题才用胭脂。来源、项目、事实类型不再各配一种颜色：时间轴每行已经写了来源名，项目和事实类型有文字和图标。

## 3. 字体

一页最多 4 种字号，从下面 5 级里取：

| 级别 | Mac | 网页 | 用途 |
| --- | --- | --- | --- |
| caption | 11 | 12px | 时间、计数、次要说明 |
| body | 13 | 14px | 正文、列表、按钮 |
| title | 17 | 18px | 卡片标题、分组标题 |
| heading | 22 | 24px | 页面主标题、日期 |
| display | 26 | 28px | 只用于"此刻"的一句话摘要 |

- 宋体只用于 title 及以上级别的叙述性文字（摘要、事项标题、日期），正文和说明都用系统无衬线。
- 等宽字体只用于路径、命令、代码、端口。时间和数字用无衬线的等宽数字（Mac `.monospacedDigit()`，网页 `font-variant-numeric: tabular-nums`）。
- 不用斜体、不用全大写、不加字间距。
- 正文行高 1.5；宋体摘要 1.6。段落间距 = 一行正文的高度。

## 4. 形状与层次

- 圆角三级：控件 6、分组 10、浮层 14。嵌套时内层 = 外层 − 间距，间距大于外层圆角时内层直角。
- 页面是平的：不加阴影、不发光、不加毛玻璃。阴影只给菜单、弹窗、菜单栏面板这类真正浮起来的东西。侧栏和菜单栏面板透出后面的内容是产品规则，保留。
- 不卡片套卡片：卡片里的子项用分割线或留白分开，不再加底色框。
- 间距用 4 的倍数：4、8、12、16、24、32。
- 动画只用于状态变化（展开、出现），时长 0.2 秒以内，不做悬停放大。

## 5. 文案与数字

- 能用布局和控件说清楚的不写说明；说明一句话说完，不用括号补充。
- 不用 `·` 拼接，改用逗号或分栏；"3 段，共 11 秒"。
- 数字带单位且说明指什么："活跃 9 小时 27 分""12 条"；千位用逗号；时长 ≥ 1 小时写"x 小时 y 分"，不足 1 分钟写"不到 1 分钟"。
- 文件大小只在详情里出现，列表里不出现字节数。
- 删除等不可逆操作才二次确认；可撤销的操作直接执行，给撤销。危险按钮只染文字，不铺红底。

## 6. 自查

- 这一页有几种字号、几种颜色？
- 每一段说明删掉以后，用户还能不能看懂？能的话就删掉。
- 窗口拉到最小（Mac 1080×640）和最大时，网页在 390px 宽时，有没有截断、重叠、横向滚动？
- 深色、浅色都看一遍。

## 7. 设置回归检查

原生设置不能把按钮藏在合并的静态辅助功能文本里。2026-11-12 的回归场景：macOS 分组 Form 中，`LabeledContent` 内的按钮可见，但辅助功能树只暴露标签。交互行统一使用保留子控件的 `SettingsRow`。

每次修改设置布局后，在安装后的应用检查：

1. 数据源详情开启一个可运行的来源，辅助功能树里必须有独立的“运行”按钮，点击后运行时间与结果更新。停用后配置仍可见。
2. AI 工具每项的连接/断开、AI 模型的测试连接、后台服务的浏览器入口、维护操作都必须暴露独立按钮；检查时不实际断开现有工具、不执行破坏性操作。
3. 安装示例插件：必填配置空值会报错；填好后安装默认停用，配置输入框只显示一次标签；更新重新展示权限并保留兼容配置，取消不改变安装内容。
4. 全局暂停时已启用来源仍保留开关选择；恢复后继续运行。登录自启关闭再开启时，当前三个服务的 PID 不变；安装升级保留自启选择。
5. 卸载弹窗提供保留记录与真删记录两个明确选项；真删链路在隔离数据库里运行 HTTP 验证，不删除真实记录做试验。


## 8. 命名、待确认和维护回归（2026-11-13）

- 待确认的声纹命名和项目改名：用中文输入法连续输入拼音，候选框应紧贴字段，选字后文字留在字段；首次 Enter 选字，后续确认才提交。取消不修改记录。分别检查窗口移动前后、正常窗口和最小窗口。用户报告过气泡候选框落到屏幕左下角；保留气泡交互，不能以替换成 sheet 代替根因修复。
- 待确认操作：卡片在 340pt 与 560pt 宽度时，按钮文字完整且不折成两行；放不下整颗按钮换行。“继续使用后会自动归档”单独成行，不与操作争宽度。
- 维护：三个导入/同步操作与按日期整理的说明留在各自分组里；展开读取/去重/整理详情后，三行从左侧开始，不漂在中央。检查正常和 1080×640 窗口。
- 音频保留：键盘直接输入 30，保存后重新进入仍为 30；选择不自动清除后保存，再进入仍保留选择；测试不改用户正式设置。0 是接口约定，界面显示“不自动清除”。

本轮核对结果：正式安装的深色正常窗口中，待确认按钮完整、隐私清单移除、音频天数可直接输入且“不自动清除”选项可选；没有提交测试姓名或修改正式保留期（仍为 60 天）。网页版用独立合成 API 验证 30 天保存、不自动清除保存及重新加载，0 天输入不会意外切到不自动清除；390px 深色和桌面浅色无横向溢出。当时命名被改成 sheet，系统输入法候选位置尚未验证；用户随后要求恢复气泡，该交互替换已撤回。后续定位结果见第 10 节。

## 9. 运行记录验收（2026-11-13）

- Mac 和网页入口均为“运行记录”，分模型整理、AI 工具读取、后台运行。列表不展开正文，进入调用详情后查看发送与返回内容；明确区分返回、校验和采用状态。
- 真实安装后检查了新 Codex 调用：输入快照可读、CLI 可见性说明明确、返回及校验通过、最终显示已用于更新。AI 工具读取可展开“查看当时带入”，正文与当次自动带入一致；旧调用不伪造正文。
- 网页合成数据检查桌面深色、390px 浅色布局，调用详情无横向溢出。Mac 实机检查了正常与缩窄窗口的列表/详情、维护展开说明，文字左对齐且可滚动。
- 当时声纹表单的英文键入和取消正常，但没有完成中文候选框验收；随后用户要求恢复气泡，见第 10 节。
- 自动验证：527 项 Bun、171 项 Swift 测试通过；后端/网页 TypeScript 检查、网页构建、Mac release 构建与安装通过。隔离的正式加密库副本迁移保留 69105 条记录，100 条原文经 107 页完整回读，真实本地 HTTP 删除与迟到响应、重开数据库、7 天过期清理通过。删除试验未操作正式原始记录。
- 固定样本：事项 `01M79NQAVM73752FFXNCRAZRHG` 的同一组 143 条记录，经新启动的已安装 MCP 全部读回（357706 字符）；11 条 support、132 条 activity，13 条标题含 Wait。相比修改前原文 ID 返回 404，可追溯性已修复；记录数量和 Wait 噪音未减少。这不是 143 条内容全正确的证明。
- 自动带入当次为 721/800 估算 token，5 项都带摘要截至时间，2 项标记待整理。旧事项摘要仍可能与新事项状态不一致；本轮不声称消除全部跨事项矛盾或达到整体准确率。正常使用日的稳定性、人工标注的正确/陈旧/归错比例仍需另做持续抽查。
- 安装后的正式库只读核验：schema v11、完整性检查 ok、迁移备份 0 份；当时 69171 条原始记录。新启动的安装目录 MCP 已包含 cursor 定义，149998 字符真实长记录通过 10 页完整回读。正式新调用的输入 33749 字符、输出 1209 字符均已加密落库，状态为 returned / passed / applied。

## 10. 恢复命名气泡与输入法定位（2026-11-13）

- 用户明确要求恢复原交互。声纹“填名字”和项目“改名”恢复同一处原有 popover、220pt 输入框、16pt 内边距、确定按钮；保留此前独立的卡片按钮换行修复。
- 临时探针只读取输入客户端、焦点窗口、marked/selected range 及屏幕坐标，不记录输入文字。实际中文组合态 `{0,1}`、`{0,2}` 中，客户端及 first responder 同为 `_SystemTextFieldFieldEditor`，key window 为 `_NSPopoverWindow`，二者窗口编号一致；字符矩形从 `(626,592,7.20,16)` 到 `(626,592,14.55,16)`，位于输入视图 `(624,592,212,16)` 内。用户当次确认“可以了”。
- 这次未复现候选框落到左下角，正常坐标不能反证此前报告，也不能证明具体根因。没有据猜测增加延时、抢焦点或坐标补丁。临时探针在最终构建前移除。
- 回归操作：声纹和项目气泡各检查首次打开、关闭重开、移动主窗口后、缩窄窗口后，用实际中文输入法输入拼音并观察候选框紧贴字段；首次 Enter 只选字，后续确认才提交；点外面关闭不保存。若再次跑偏，应在故障保持时采集实际查询范围、返回矩形和焦点窗口，再决定修复。
- 移除探针后的版本已构建并重装，171 项 Swift 测试通过；安装二进制与构建产物 SHA-256 一致且不含探针路径，命名气泡实现与本轮改动前版本逐字核对一致。用户已确认无探针版本连续两次输入、关闭重开后的候选位置均正常，本次恢复交互的实用复验通过。原故障仍未复现，不能记为根因已解决；窗口移动和缩窄后的中文候选位置未在这次人工确认范围内。
